# RUST-BOTS-002 — безопасное обновление Rust + Oxide

Статус: **DESIGN ONLY / NOT STARTED**. Требования сохранены по дополнению владельца от 03.11.2026. Не запускать эту задачу или настоящее обновление в рамках 001. Приоритет 001 — доказанный автономный навигационный E2E; его сетевой блокер остаётся в RESULT 001.

## Outcome и границы

Одна команда PowerShell 5.1+ из любого cwd обновляет остановленный RustDedicated (Steam app 258550, явная ветка public), затем устанавливает проверенный совместимый стабильный Oxide.Rust, сохраняя owner plugins/config/data и мир. Ошибка не должна запускать сервер автоматически. Скрипты/модели/fixtures и безопасные шаблоны находятся в Git вне Server/. Сам Server/, сырые бэкапы и секреты никогда не публикуются. Текущие fail-closed update.bat и scripts/templates/update.bat остаются заблокированными до реализации и проверки этого процесса.

Изученные локальные исходные файлы 001: Run_DS имел безусловный restart; update.bat вызывал внешний runscript; update_script.txt содержит anonymous login, app_update 258550 validate и quit, без явной public и без Oxide restore. Файлы не исполнялись. Новый updater не должен молча запускать этот старый runscript; создать собственные управляемые параметры с public. Validate — только если обосновано отдельным решением, не обязательный default. Запуск сервера отделён от update и автоматом после ошибки не выполняется.

## Предложенный процесс

1. **Plan (default, без мутаций).** Проверить пути/links, отсутствие Rust/client/SteamCMD и занятых ресурсов; при любом чужом процессе отказать, а не останавливать его. Инвентаризировать source/target build, владельческие каталоги и объём бэкапа. Не запускать SteamCMD ради получения metadata. Разрешённые источники версий установить по официальным данным и локальным manifest/DLL, не угадывать.
2. **Release discovery.** HTTPS GET `https://api.github.com/repos/OxideMod/Oxide.Rust/releases/latest`; проверять официальный owner/repo, HTTP code/content/размер, draft=false, prerelease=false и asset state=uploaded. Выбирать ровно Windows asset с точным именем `Oxide.Rust.zip`, а не tarball, Linux ZIP или произвольную ссылку из release body. Не предполагать, что asset существует/уникален или всегда содержит digest.
3. **Source и integrity.** Сохранять release ID/tag/asset ID/размер/URL и ожидаемый SHA-256 из доверенного официального release asset digest либо другого подтверждённого publisher manifest. Скачать в ignored staging, вычислить SHA-256 и сравнить с ожидаемым значением; собственный только что вычисленный hash без эталона не доказывает происхождение. Отсутствие доверенного digest — BLOCKED, без SteamCMD. Проверять HTTPS и допустимую цепочку GitHub release-redirects, не принимать произвольный host/path. В тестах — имитации HTTP/redirect/download, никаких настоящих архивов.
4. **Compatibility gate ДО SteamCMD.** Требуется проверяемое соответствие целевого Rust build/protocol/assembly fingerprint и выбранного Oxide release. `latest`, время релиза и рост версии сами по себе недостаточны. API latest не является compatibility oracle. Если официального машиночитаемого соответствия нет, зафиксировать этот blocker; допустимый путь — pinned compatibility evidence и проверенная изолированная staging-копия целевого runtime с Oxide load/plugin smoke. Не менять production для эксперимента. Сверить target public build ещё раз перед apply; при изменении плана повторно отказать.
5. **Backup gate.** Полный восстанавливаемый локальный snapshot installation и hash manifest, включая patchable binaries, owner plugins/config/data/lang, configs, мир/сейвы и метаданные. Проверить полноту/читаемость/свободное место и restore в fixtures до update. Не hardlink/junction writable owner файлы. Бэкап вне public Git; запись с уникальными CreateNew paths, marker и exact scope.
6. **Apply (явный отдельный режим).** После успешного plan и явного действия владельца обновить app 258550 branch public через SteamCMD с абсолютными путями и контролируемым cwd. Обработать exit code и неожиданный build drift. Действующий Server нельзя обновлять в 001 даже при готовом плане/пакете.
7. **Oxide install.** Сначала проверить ZIP entries на traversal/absolute paths/links, дубликаты, размер/zip-bomb и допустимый install scope. Распаковать в staging, подтвердить ожидаемые DLL/версии/хеши. Применять только подтверждённые runtime файлы; не перекрывать owner oxide/plugins/config/data/lang/server/cfg/config. Учесть прерывание между Rust update и Oxide install, вести локальный journal с recovery state.
8. **Verify и recovery.** Проверить target build, установленный Oxide и неизменность owner data. Live plugin smoke сначала в изолированной копии, с сетевой изоляцией/owned process/shutdown. Успешный updater также не обязан автоматически запускать игровой сервер: запуск отдельной командой. Любой сбой — диагностический статус и отказ от автозапуска. Restore предлагать только при проверенном backup/journal и отсутствии foreign process; восстанавливать exact affected scope, сохраняя исходный backup. Если восстановление не доказано или возникли concurrent changes, остановиться и объяснить границу, а не обещать полный rollback.

## Выборочное сохранение конфигураций

Owner Oxide configs — источник истины для соло-игры; их нельзя сбрасывать/массово заменять. Экспорт — отдельная явная команда: exact выбранные файлы и allowlist полей, положительная схема публичных значений, нормализация и замена private values плейсхолдерами. По умолчанию deny неизвестных полей; blacklist известных паролей недостаточен. Steam IDs, IP/пути владельца, пароли, API tokens/webhooks и runtime данные не экспортируются. Не публиковать config целиком ради удобства и не превращать export в apply: изменение действующих конфигов требует отдельного явного пути. Safe examples — искусственные значения вне Server/. Preview и secret/encoding scan обязательны до exact-path staging. Исходник собственного бота — C# Oxide plugin в src/plugins, рабочая копия — в локальном Server/rustds/oxide/plugins; для live диагностики всё равно нужен отдельный writable test install.

## Focused acceptance / fixtures

- Успех mock-chain: stopped → verified compatible plan+hash+backup → fake SteamCMD public → staged Oxide → owner hashes preserved → verify. Запустить команду из чужого cwd с пробелами в путях. Не вызывать настоящий SteamCMD/download/apply.
- Отказ до fake SteamCMD при отсутствии compatible release/digest/backup, API error/rate limit, prerelease/wrong asset, hash mismatch, foreign process, target drift, unsafe ZIP или linked paths. Assert ноль production writes/calls.
- Ошибка SteamCMD/частичной установки/прерывание: нет server autostart, диагностика и verified bounded restore; plugins/config/data/world hashes сохранены. Не добавлять сотни тестов: параметризованные boundary cases по реальным рискам.
- Export только явно разрешённых config fields, удаление всех private значений и отказ на неизвестных полях; исходные configs байтово неизменны.
- Smoke/build/static проверки, exact artifact allowlist, отдельные mojibake/escaped-Cyrillic scans, RESULT с честным статусом; обычные commit/push master без Server/ и без force — только когда эта следующая задача явно начата.

## Что ещё не проверено

Полный updater, совместимость конкретного будущего Rust/Oxide, текущая availability Windows asset/digest, реальный download/SteamCMD/install/rollback и config export не реализованы и не испытаны. Одного номера последнего релиза для совместимости недостаточно. Это намеренное ограничение scope 001, разрешённое владельцем, а не выполненное обновление.

Официальная справка: [GitHub latest releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release), [release asset API и digest](https://docs.github.com/en/rest/releases/assets#get-a-release-asset), [Facepunch: после Rust update требуется Oxide](https://wiki.facepunch.com/rust/creating-a-server). Поля digest/URL и metadata проверяются по фактическому ответу; API latest при просмотре 001 был недоступен через web-инструмент, сам архив не запрашивался.
