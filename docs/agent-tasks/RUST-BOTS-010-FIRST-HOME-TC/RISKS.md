# RISKS — риски и обещанные будущие функции

**R1 — структура/permissions:** серверный spawn здания может обойти native sockets/support/privileges и создать нелегальную базу. Только валидированное установленным IL/native building registration и реальная оплата. Ошибки строительства — PARTIAL/BLOCKED, не фальшивый GREEN.

**R2 — bot owner ID:** двигатель назначает `ScientistNPC` временный ID, который может поменяться после рестарта; настоящая Steam identity отсутствует. TC должен принадлежать правильной логической личности и допускает rebind только после защищённой world/wipe/owner проверке; не авторизовать чужого владельца.

**R3 — динамическая геометрия:** RustNav мог не строить путь внутрь после появления стены/двери. Не использовать телепортацию, collision disable или fake complete path. Исследовать безопасные navmesh dynamic obstacles/links; если невозможно — описать физический blocker.

**R4 — upkeep / decay:** не выдавать простое наполнение случайного контейнера за работающий TC или отключать decay; native upkeep consumption и настоящая структурная привилегия обязательны для GREEN. Не требуется ждать полный игровой день.

**R5 — стабильность ресурсов/экономики:** 009 durable depletion доказан только graceful restart, crash-atomicity не доказана. 010 не должен это маскировать; до production 50–100 ботов нужен отдельный controlled-crash proof, journal reconciliation и performance тест. При IN_DOUBT — fail closed.

**R6 — вайп:** `MapKey+WipeId` отделять от меняющегося `.sav`; новый остров не наследует старое TC/базу/upkeep. Разрушенную/захваченную TC не восстанавливать «магически». Возможность реального re-build после рейда — будущая задача.

**R7 — план развития:** после первого дома — хранение/сортировка ящиков, workbench/blueprint research, внутридомовая маршрутизация с запертыми/гаражными дверями; спальные мешки и native death/respawn; ремонт/перестройка после потери TC; затем native PvP/кланы/оборона/рейды; Giant Excavator с дизелем; позднее 50–100 identity+LOD; Semantic Pack в конце. Oil rigs/cargo optional. В этой задаче не строить 10 отдельных подсистем.

**R8 — лимит/live и личный мир:** ориентир 2 E2E, третий только с доказанной причиной; весь owner Server read-only, никаких update/SteamCMD/принудительного завершения чужих процессов. Все изменения в UTF-8 (русские сообщения читаемы), проверять mojibake и escaped Cyrillic отдельно.
