# EVIDENCE — требование к доказательствам

Кодекс создаёт `RESULT.md` в этом каталоге после исполнения. В него входят:

1. Кратко: `GREEN` / `PARTIAL` / `BLOCKED` / `FAILED`, что заработало фактически, что не заработало.
2. Инвентаризация текущего сервера: hash/version (если есть), активный runtime, плагины, список предупреждений **без имён и содержимого секретных полей**.
3. Реальный запуск: команда или сценарий запуска (без RCON-пароля), момент готовности, доказательство Oxide+plugin loaded, причины slow startup.
4. Отладочная навигация: выбранный тип NPC, сообщения sample/path/stuck/arrived; агрегаты и без умолчаний число неуспешных попыток.
5. Локальные BAT: пути и хеши бэкапов, безопасное сравнение поведения, результаты dry-run без SteamCMD; проверка, что обновлённые реальные BAT НЕ попали в Git, а опубликованы только обезличенные шаблоны.
6. Shutdown: PID только собственного сервера; подтверждение отсутствия процесса / занятых портов; отсутствие повреждения пользовательского мира.
7. Запуск тестов и итог; если нет runtime proof — именно `NOT_VERIFIED`, даже если source скомпилирован.
8. Git: baseline/final SHA, `git status`, commit paths, no Server files, push result.

Сырые отчёты и логи тестового сервера должны храниться **локально, в игнорируемом каталоге**. В публичный `RESULT.md` допустимы только обезличенные строки и показатели без ключей, IP/steamid и секретных конфигураций.

Важно: пользователь не должен открывать игру для базового теста. Ручная визуальная проверка понадобится позже и не заменяет эту E2E-телеметрию.
