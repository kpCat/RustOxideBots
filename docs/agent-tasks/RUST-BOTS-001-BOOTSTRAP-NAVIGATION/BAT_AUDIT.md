# BAT_AUDIT — исследованы вложения владельца от 03.11.2026

Здесь фиксируются факты **только из двух присланных BAT**, не из локальной среды Codex. Перед исправлениями перечитать реальные `Server\Run_DS.bat`, `Server\update.bat`, а также отсутствующий во вложениях `Server\update_script.txt`. В публичных файлах не раскрывать реальные имя, seed, identity, возможные секреты и адреса.

## Run_DS.bat — 264 байта

`echo off` → `chcp 65001` → `:start` → `cd rustds` → `RustDedicated.exe -batchmode` с фиксированными hostname, port, identity, seed, worldsize 4000, maxplayers 300 и `-logFile "output.txt"` → `cd ../` → **`goto start`**.

Обнаружено: нет SteamCMD в этом файле; рабочий каталог относителен; **при любом завершении RustDedicated моментально начинается следующий запуск**. Нет задержки, условий или проверки exit code. Это способно создавать иллюзию постоянной повторной загрузки/генерации. При неизменных seed/worldsize/identity сам батник **не доказывает** генерацию карты заново. Проверить `.map`, `.sav`, `server.cfg`, логи и события рестарта. Количество `maxplayers` не означает число NPC.

## update.bat — 61 байт

`cd steam` → `steamcmd.exe +runscript ../update_script.txt` → `cd ..`.

Обнаружено: относительные пути, нет проверок наличия файлов и результата, нет автоматического восстановления Oxide. **Содержимое `update_script.txt` не было приложено**: ничего не утверждать про `validate`, пока файл не прочитан. Facepunch прямо предупреждает: после SteamCMD-обновления нужна переустановка Oxide (https://wiki.facepunch.com/rust/creating-a-server).

## Исправления, разрешённые владельцем

1. Сначала `.gitignore`, хешированные резервные копии локальных BAT, сохранение игровых параметров.
2. Убрать зависимость от случайного `cwd`, обрабатывать exit codes, предотвращать бесконечный рестарт после нормального `quit`; если требуется опциональный аварийный autorestart — явно включаемый и останавливаемый.
3. Для апдейтера — fail-closed до SteamCMD без проверенного доступного совместимого Oxide; предусмотреть безопасный update → Oxide restore, но **не выполнять реальное обновление в 001**.
4. Проверять исправления только статически или в mock/dry-run без запуска настоящего SteamCMD.
5. Сохранить рабочие версии и бэкапы локально в `Server/` (ignored); в master коммитить только обезличенные шаблоны в `scripts/`, документацию и тесты.
6. E2E запускать EXE напрямую, не через `Run_DS.bat`; отдельные test identity и **отдельные writable Oxide plugins/config/data** обязательны, один identity недостаточен.

Оригинальные BAT в ZIP намеренно не включены: реальные файлы доступны Codex внутри `Server/`, а публичный Git не должен хранить пользовательские конфигурации.
