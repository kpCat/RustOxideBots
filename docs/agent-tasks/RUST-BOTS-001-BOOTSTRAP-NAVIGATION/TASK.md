# GOAL / TASK: RUST-BOTS-001-BOOTSTRAP-NAVIGATION

## Outcome: не «отчёт ради отчёта», а работающая проверяемая вертикаль

1. Репозиторий безопасен для публикации, `Server/` целиком игнорируется; нет игровых бинарников, конфигов, сохранений и секретов в Git.
2. Добавлен воспроизводимый автономный тестовый запуск RustDedicated, который не обновляет Rust/Oxide, не использует пользовательский мир и не оставляет собственный сервер работать после выхода.
3. Разработан минимальный C# Oxide-плагин диагностической навигации NPC. При возможностях текущей установленной сборки он создаёт **одного** NPC, задаёт несколько достижимых целей, показывает физическое изменение координат / прохождение и сохраняет честный результат живого испытания.
4. Измерена причина долгого старта по логам/параметрам — без обещаний, что сама запись «Generating procedural map» доказывает повторную генерацию.
5. Улучшены `Run_DS.bat` и `update.bat` с локальными бэкапами, без обновления Rust/Oxide; безопасные шаблоны хранятся в Git, реальные BAT — только в игнорируемой `Server/`.
6. Код, сценарии и документация коммитятся и пушатся в `origin/master` обычным fast-forward push. Поставленный артефакт задачи также включён в коммит.

## Обязательный порядок работы

### A. Baseline + запреты до любых тестов

- Проверить `pwd`, репозиторий, `git remote -v`, активную ветку, `git status --short`, `origin/master` и исходный коммит. Удалённая ветка `master` уже создана (на момент постановки задачи — только README.md), сверить повторно.
- Проводить работу только в `D:\Codex\repos\RustOxideBots\`; не создавать второй Git-репозиторий.
- Проверить, не работает ли **чужой / пользовательский** `RustDedicated.exe` и нет ли активной игровой сессии. Если запущен пользовательский сервер, НЕ останавливать, НЕ пытаться занять его порты; провести статическую часть и отчёт о блокировке тестов.
- Инвентаризировать `Server\Run_DS.bat`, `Server\update.bat`, **`Server\update_script.txt`**, `Server\loadMod.bat`, папки `rustds\oxide\plugins`, `config`, `data`, `server` и фактический RustDedicated.exe. Существующие пути могут отличаться — фиксировать обнаруженные.
- Не исполнять `update.bat`/SteamCMD/`validate`; не переустанавливать Oxide; не менять DLL или бинарники сервера.

### B. Сначала Git-изоляция

- Создать root `.gitignore`: **вся** `/Server/` включая её содержимое; локальные runtime-секреты, отчёты и временные дампы; `bin/`, `obj/`, `.vs/`, логи, дампы, локальные настройки IDE и приватные ключи.
- Исходный код собственных модов хранить под `src/`, тестовые скрипты в `scripts/`, задачи/документацию под `docs/`. Не включать чужие плагины без лицензий и разрешений.
- До первого `git add` выполнить проверки `git check-ignore -v Server/...` на фактических файлах, `git status --ignored --short`, затем `git add -n -- <точные пути>` и проверить, что все пути вне `Server/`, а также нет секретов. Не использовать `git add .`, `git add -A`, `git clean`, `git reset --hard`, stash, force push.
- Добавить корневой `AGENTS.md` с правилами защиты локального сервера, отсутствия потерь и запретами на самовольные апдейты. README проекта — краткий обзор и инструкции.
- НИКАКИЕ значения из действующих конфигов не переносить в Git. Примеры параметров должны быть искусственными, с явными плейсхолдерами. Логи коммита проверять на пароли / токены / steam ids / реальные пути секретов / приватные данные.

### C. Базовая диагностика сервера и модов

- Прочитать реальные `Run_DS.bat` и `update.bat`, записать: точный exe, `cwd`, ветку SteamCMD (если есть), параметры `server.identity`, `server.seed`, `server.worldsize`, `server.level`, порты, `batchmode`, `-logfile` (в публичных документах скрыть RCON пароль и другое секретное содержимое).
- При чтении реального `Run_DS.bat` учитывать обнаруженный в присланном файле **безусловный `goto start`**, который немедленно перезапускает процесс после намеренной остановки; SteamCMD в полученном `Run_DS.bat` отсутствует. В `update.bat` найден `+runscript ../update_script.txt`, но реальное содержимое `update_script.txt` НЕ было прислано — проверить локально. Не выполнять update/validate. См. `BAT_AUDIT.md`.
- По существующим файлам `.map`, `.sav`, timestamp и журналам выяснить, генерируется ли карта реально каждый старт либо загружается готовая. **Не удалять/переименовывать никакие карты или сохранения**. Измерить временные фазы: process start → world load/process → Oxide load → plugins load → `Server startup complete`.
- Составить инвентарь плагинов: имя, версия (если известна), состояние загрузки, ошибка компиляции или исполнения, необходимость обновления. Определять устаревание **по фактической ошибке**, а не только по возрасту файла.
- Никаких массовых удалений, сбросов конфигов или автоскачивания сторонних модов. Проблемный плагин можно временно отключить **только в изолированном тестовом контуре**, с полным восстановлением в `finally`, или исключить тестовую конфигурацию; всё сделать обратимым. Существующие конфиги пользователя — источник истины, не перезаписывать.

### C2. Улучшить два BAT и защитить пользовательскую конфигурацию (дополнение 03.11.2026)

Владелец отдельно **разрешил улучшение** `Server\Run_DS.bat` и `Server\update.bat`; сервер уже обновлён, запускать SteamCMD/апдейтер нельзя. Сначала перечитать локальные файлы и `BAT_AUDIT.md` (присланные вложения могли отличаться от актуальных копий).

- Перед заменой создать **локальные резервные копии** оригинальных BAT в `Server/`, зафиксировать хеши; не публиковать содержимое и значения владельца. Сохранить БЕЗ изменений действующие параметры игрового мира, seed, identity, имя, размеры, порты и maxplayers. Не менять сохранения, Oxide-конфиги и сторонние моды. При невозможности безопасной проверки оставить оригинал, предложить новый вариант и честный PARTIAL.
- `Run_DS.bat`: сделать независимым от текущего каталога (`%~dp0`, `cd /d` или `pushd`), проверять наличие exe и exit code, убрать **безусловный немедленный `goto start`** после чистого выхода. Если нужен авторестарт на аварии — только отдельный явно выбранный режим с задержкой и понятным способом остановки; нормальная остановка обязана завершить запуск. Никакого SteamCMD при старте.
- `update.bat`: исправить `cwd`, проверить существование SteamCMD и `update_script.txt`, обработать код возврата. Подготовить **безопасный fail-closed процесс**: без заранее проверенного совместимого пакета Oxide и способа его восстановить после обновления Rust настоящий SteamCMD не запускать. Перед реальным апдейтом (вне 001) нужны проверка совместимости, резервная копия, явное действие пользователя и проверка успешной переустановки Oxide. Если восстановление не гарантировано — отказаться от обновления ДО SteamCMD. В 001 **никогда не вызывать реальный `update.bat` и SteamCMD**; тестировать обвязку только dry-run/mock/stub.
- Улучшенные рабочие BAT остаются локально внутри исключённого из Git `Server/`. В репозиторий коммитить только **обезличенные** шаблоны/утилиты/тесты `scripts/` и инструкции; реальные параметры/пароли/Steam ID не публиковать.
- Проверить отдельными сценариями: запуск BAT не из его папки, выход с кодом 0 без повторного старта, отказ апдейтера при отсутствии Oxide-пакета/SteamCMD/update_script.txt, отсутствие вызова настоящего SteamCMD. Записать в `RESULT.md` пути бэкапов, хеши, краткий diff без приватных данных и инструкцию владельцу.

**Критическое дополнение к изоляции E2E:** отдельная `server.identity` изолирует мир и сейвы, но **не изолирует автоматически записываемые каталоги `oxide/plugins`, `oxide/config`, `oxide/data` той же установки**. Нужна доказанная отдельная test install root/писаемые Oxide-каталоги и логи (не связывать их hardlink/junction с игровым миром). Можно оптимизировать размер/копирование, но не жертвовать целостностью основного сервера. Если изоляция не доказана — PARTIAL/BLOCKED, без live-test.

### D. Самостоятельный headless test harness

Создать и проверить `scripts/` (PowerShell 5.1+ предпочтительно, допускаются дополнительные минимальные C# инструменты), работающий на Windows и запускаемый из корня репозитория. Понятная команда в README, без ручных сложных CLI параметров.

- Запуск именно существующего RustDedicated **без SteamCMD и без автоматического рестарта**. Проверить рабочую папку / артефакты Oxide; не обращаться к пользовательскому `Run_DS.bat`, если он выполняет update/validate и/или цикл `goto`.
- Отдельная test `server.identity`, **изолированные записываемые Oxide plugins/config/data**, порты, RCON пароль (случайно создаваемый и сохраняемый только в игнорируемом локальном runtime-файле либо передаваемый безопасно), test save/data. Не подключаться к интернет-сервисам и не открывать тестовый RCON наружу; если нельзя безопасно ограничить доступ — блокировать тест и объяснить. Не менять `seed/worldsize/level` пользовательского мира.
- Проверить и документировать использование карты/кэша; при необходимости изолированная test identity может повлечь разовую генерацию карты — не считать ошибкой и не трогать существующие сохранения.
- Ждать подтверждённой готовности сервера (например, `Server startup complete` + проверка Oxide/тестовой команды), не считать один лишь факт существования процесса успешным стартом.
- Логи, временные данные и результаты в игнорируемых каталогах `artifacts/runtime` либо `.local` (не в папке задачи, чтобы исключить утечку).
- Процесс контролируется строго по **PID / process handle + происхождению запуска**, а не по имени. При любых исходах выполнить graceful shutdown (`quit` / RCON с подтверждением, если доступен), дождаться выхода, только затем ограниченный принудительный stop СВОЕГО дочернего процесса / его дерева. Никогда не останавливать чужие `RustDedicated.exe` и никогда не оставлять собственный экземпляр висеть после теста. Операции завершения/очистки — в `try/finally`.
- Если обнаружен уже запущенный чужой процесс или заняты необходимые порты: **BLOCKED, без чужого shutdown**. Если сервер стартует слишком долго — ограниченная диагностика, лог и stop, без бесконечного ожидания.
- Не выполнять wipe, не стирать карту, серверные данные, конфиги, игровые сохранения.

### E. Живой диагностический NPC: `RustBotsNavigationProbe.cs`

- Рабочий исходник в `src/plugins/RustBotsNavigationProbe.cs`, тестовый развёртываемый экземпляр в `Server/rustds/oxide/plugins/` (эта копия остаётся вне Git). Не копировать декомпилированный чужой код целиком в публичную репку.
- Перед кодом изучить **актуальные установленные** `Assembly-CSharp.dll` и Rust/Oxide API. Сравнить старый `NPCPlayer`/`ScientistNPC` с `ScientistNPC2`, `BaseNPC2`, `Rust.Ai.Gen2.RustNavMeshAgent`; проверить, какая система реально активна и что исполняется для выбранного NPC. Не считать старый `NavMesh.SamplePosition` достаточной проверкой для RustNav.
- Выбрать реально работающий доступный **человекоподобный NPC**. Пояснить компромисс между моделью NPC и возможностями BasePlayer, не подделывать живые Steam-соединения.
- В тестовом режиме по явной команде (или безопасному test-only автостарту) создать **одного** NPC в проверенной открытой области. Проверить: корректная высота, клиренс/коллизии, наличие NavMesh, возможность уйти с позиции. Ни одного NPC в пользовательском мире по умолчанию.
- Попытаться провести NPC через **минимум 3 выбранных динамически, проверенно достижимых**, не фиксированных для конкретной карты цели; использовать штатный навигационный агент и реальные игровые шаги, а не бесконечный `MovePosition`/телепортацию. Измерять фактический путь, смещение по координатам, elapsed, цель, `path status`, stuck/repath, тип NPC, активный nav backend.
- Начальный результат может быть небольшим: ориентир для GREEN — 3 последовательных успешных целевых перехода с суммарным фактическим перемещением >= 60 м и без телепортаций после рождения, при этом хотя бы один переход >= 20 м. Если в данной сборке путь невозможен, вернуть BLOCKED с воспроизводимым точным объяснением и логом, **не симулировать успешный результат**.
- Написать безопасный watchdog: если агент «Moving», а смещение почти нулевое — фиксировать `STUCK`, попытка bounded repath/альтернативной точки, далее fail. Никаких бесконечных retry.
- Отдельно отметь, что эта первая проба не доказывает длительное движение через всю карту, монументы, обход домов или поведение настоящего игрока. Ни фарм, ни крафт, ни PvP, ни строительство в этой задаче не делать.
- Исходник должен компилироваться именно установленным Oxide и тестироваться на живом сервере; простой синтаксический успех не считать GREEN.

### F. Проверки и публикация

- Статические проверки `scripts/` и BAT (без настоящего update), корректность PowerShell, отсутствие открытых PID и временных небезопасных портов после теста.
- E2E: запуск из чистого «не запущено» → readiness → Oxide loaded → plugin loaded → тест движения (или честный BLOCKED) → управляемый shutdown → тот же процесс отсутствует. Приложить обезличенные журналы и метрики, не публикацию секретов.
- 1–2 полноценных загрузки сервера по необходимости, не превращать исследование в бесконечные повторные пуски. Ограничить повторные попытки работы с одним классом ошибок. Если окружение реально блокирует E2E, оставить воспроизводимый harness и точный шаг для следующего захода.
- Прочитать `ACCEPTANCE.md`, `EVIDENCE.md` и заполнить итоговый `docs/agent-tasks/RUST-BOTS-001-BOOTSTRAP-NAVIGATION/RESULT.md`. Статус один из `GREEN`, `PARTIAL`, `BLOCKED`, `FAILED` с точными достижениями, без подмены.
- Сверить diff + объём коммита + список путей + секреты. Сделать `git add -- <точные разрешённые пути>`, `git commit`, `git push origin master` без force. Повторно проверить актуальный SHA `origin/master` и `git status --short`; если у пользователя есть другие незакоммиченные файлы, оставить их без изменений и честно описать.
- Если push невозможно сделать по объективным причинам (auth/conflict/секреты), НЕ обходить защиту: дать точную ошибку и состояние. Никогда не коммитить `Server/` ради выполнения требования.

## STOP / NON-GOALS

Нельзя: обновлять Rust/Oxide, запускать `Server/update.bat`, удалять старые моды и конфиги, делать wipe, публиковать `Server/`, строить полноценный AI-социум, крафт/рейды/PvP, подключаться игровым клиентом владельца, подменять реальные игровые метрики синтетикой, заставлять владельца входить в игру, запускать сторонний DLL injector, вмешиваться в сторонние или уже запущенные процессы.

Остановиться, если не можешь доказать безопасность test identity или владения процессом, если требуется необратимое изменение пользовательского сервера, обнаружен секрет в staged files или отсутствует совместимый runtime. Принести частичный безопасный результат.
