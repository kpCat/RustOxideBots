# GATES — защита от ложного GREEN и расходов лимитов

1. **Installed API gate**: local DLL fingerprints и IL рецептов/очереди/blueprints/workbench. Не начинать длительный Rust startup, пока неизвестен реальный доступный позитивный рецепт и способ списания настоящих Item. Если рецепт в runtime не найден — BLOCKED с API evidence, не придумывать его.
2. **Actor/equipment gate**: `ScientistNPC2` не `BasePlayer`. Наличие у него ItemContainer не означает PlayerInventory. Статус crafting `SERVER_ACCOUNTED_CRAFT`, пока *конкретная* native queue/ingredient debit для actor не доказана live. Нельзя создавать фальшивую Steam identity.
3. **Ingredient gate**: натуральная добыча разрешённых материалов из текущих resource pools (004 adapter с явной маркировкой). Source pool должен уменьшиться до начисления. Рецепт оплачивается только Item'ами в реальном inventory. Недостаток ингредиента останавливает крафт без изменений.
4. **Recipe gate**: ItemBlueprint actual output/ingredients/amountToCreate/workbench/unlock. На экспериментальной карте и в нынешней сборке часть полей/правил может отличаться; проверить установленные методы. Не выбрасывать workbench/blueprint проверки только для получения GREEN.
5. **Negative gate**: одна реальная попытка запретного рецепта в **том же** live process до положительного крафта или после, с 0 изменений. Выбрать причину из установленного API (ингредиенты, locked BP или workbench). Отдельные статусы по причинам; один отрицательный gate не доказывает все три.
6. **No double-credit**: exact UID/amount ledger; повторный вызов с тем же intent не должен начислять второй output. Нет ресурса из воздуха. Инвариант: original inventory - consumed ingredients + actual crafted outputs = inventory result (с учётом recorded starter kit и raw harvested input).
7. **Persistence gate**: второй независимый server process читает native inventory + actor snapshot с точным complete world proof. Совпадают сохранённые значения, new output UID, state/craft completion. Без второго процесса `PERSISTENCE=NOT_VERIFIED`.
8. **Safety gate**: owner world и configs неизменны, tests сами очищают owned процессы, порты, firewall/leases. Не начинать тест при уже запущенном постороннем Rust. Чистота тестов и публикации проверяется отдельно.
9. **Budget gate**: максимум 2 full E2E и только 1 условный extra при конкретной неисправности. При провале без безопасного доказуемого исправления — PARTIAL/BLOCKED, не бесконечные рестарты ради GREEN.
