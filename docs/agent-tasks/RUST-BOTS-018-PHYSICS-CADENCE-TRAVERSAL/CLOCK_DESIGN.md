# CLOCK_DESIGN — separate physics correctness from scheduler latency

**Known failure:** existing `WallProblem()` treats real-time callback jitter >100ms as an invalid physics witness even if native FixedUpdate sequence and fixed steps are contiguous. BENCH4 0.1031844s, BENCH5 0.125893s. `currentClock.Delta=0.0625`, fixed step and sequence correct in both reports. An unconditional `MaxTick=.1` wall veto is not a valid inference of a physics skip.

Do NOT solve by changing `MaxTick` globally, using an unexplained 0.2–0.3s allowance, lying about wall timestamps, or crediting a terminal-only after-geometry receipt. Need explicit model with **3 independent clocks / risks**:

1. **Physics integration clock**: exact installed FixedUpdate context, `Time.fixedTimeAsDouble`, `fixedUnscaledTimeAsDouble`, actual `fixedDeltaTime`, monotone driver Sequence, physics mode, timeScale. It owns movement distance, velocity, acceleration and accepted native witness horizon. Skipped/duplicate/reordered/changed physics step => FAIL-CLOSED; no adaptive gaps.
2. **Wall/scheduler clock**: `realtimeSinceStartupAsDouble` monotonic and bounded total route deadline. Log latency `callback-to-callback` and `read-at-tick`. Scheduler lag alone does NOT imply unobserved physics. A consecutive fixed step with new valid pose+support+collision/UID/world can be accepted as one fixed-step movement even after a delayed wall callback **only after separate proof**. Track lag statistics and explicitly distinguish `WALL_LATE_PHYSICS_CONTIGUOUS`, `WALL_LATE_PHYSICS_SKIPPED`, `WALL_LATE_UNKNOWN`.
3. **Safety/watchdog**: independent real-time deadline for route/task, sensor budget, excessive single callback runtime, broken sequence, non-contiguous fixed times or missing movement writer. For unusually long stalls, choose a bounded action: prove the pending command on the very next valid physics callback, optionally enter a physically supported `LAG_RECOVERY`/braking mode with no new unobserved command; or stop if cannot safely prove. Never silently reinterpret a truly unobserved motion as observed. The exact upper bound and recovery policy must be justified by installed API/live timings and independently reviewed; not an arbitrary tolerance escalation.

**Potential implementation approach (a proposal, not a proven repair):** separate `WallTelemetry` from `PhysicsClockProblem`. When wall gap is large but actual native `Sequence/fixedTime/mode/TimeScale` is strictly contiguous, evaluate pending command's usual observed witness at the single actual step, with identical original full-volume/sweep/body/support/velocity/accel gates. Then distinguish `SCHEDULER_LAG_ACCEPTED_PHYSICS_WITNESS` (only genuine complete witness) from non-contiguous or missing data (STOP). No `STEP_RESOLVED`/`FLOOR_ACQUIRED` credit from wall gap itself. If sampling is coarse or callbacks were skipped, stop even if current endpoint looks safe. Consider real-time task watchdog separately; the wall-time deadline must never be silently extended.

**Hard cases to test before any native PID:**
- Wall gap 0.1031844s and0.125893s with contiguous sequence/fixed time and actual valid command witness should not automatically STOP **if** rechecked native pose/sweep/support validates.
- Same gaps with a skipped Sequence, changed physics time, double callback, timeScale !=1, simulationMode changed, missing/undefined native velocity, foreign/body collider, actual target divergence or acceleration violation -> must fail closed.
- A long (> selected justified watchdog bound) real-time stall, missing fixed callbacks or stale transform -> distinct `LAG_UNKNOWN` or true STOP, never fabricated witness. Include catch-up batch callbacks with very close wall timestamps, physics time still advances each actual step.
- Pending command at wall stall and nonzero lastVelocity: no abrupt implicit rest or new goal. A `BRAKE_HOLD` may only be issued if physical acceleration limit and full support/sweep/observed subsequent stop allow it. Otherwise STOP. Old `CLOCK_UNOBSERVED_ACTIVE_HOLD` test remains meaningful.
- Full path and building cases must use unchanged continuous physics-body evidence; clock workaround never disables wall/door/foreign/threshold checks.

**Verification:** offline RED→GREEN contracts on frozen receipt structures and synthetic clock sequences, reference the exact BENCH4/5 historic values, do not rewrite old raw or turn its earlier rejected witnesses into historical PASS. Native warmup can be used to diagnose, but 2s stable warmup must NOT be interpreted as guarantee of no subsequent jitter.
