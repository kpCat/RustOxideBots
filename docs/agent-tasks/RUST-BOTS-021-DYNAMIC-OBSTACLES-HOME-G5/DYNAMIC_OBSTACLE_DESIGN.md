### Политика для универсальной навигации, без боевого AI

1. **Категория**: живой `BaseCombatEntity`/native animal/player/vehicle/dynamic collider, если installed DLL действительно поддерживает эти типы. Классифицировать по real entity+collider, не по строке "Wolf2" и не только `attachedRigidbody`: у сущности collider может быть без Rigidbody. Статическую собственную постройку и чужие объекты нельзя игнорировать. Сохранять exact instance/network/prefab/category, timestamp/position/rotation, finite bounds/velocity (лишь если native измерено).
2. **До выдачи команды**: по original 0.5m capsule и full-time FixedUpdate проверить текущий и будущий swept corridor, конечную точку, поддержку и occupancy в пределах только фактически наблюдаемых объектов. Консервативная safety envelope для подвижного препятствия на реальном горизонте (не изменять collider/world). Информация устарела/объект переместился/скорость неизвестна → отказ в выдаче команды и точный reason `DYNAMIC_UNCERTAIN`, а не `Clear=true`.
3. **Если NPC ещё вне препятствия и стоит**: режим `DYNAMIC_WAIT` с реальными фиксированными кадрами/новыми физическими замерами, ограниченным временем/числом попыток, неизменным body и owner. После устойчиво свободного маршрута + свежего native PathComplete разрешён обычный переход. Альтернатива — bounded реальный обход по RustNav с полноценным original-body swept clearance; только без скрытого перемещения, не через TC/door/wall. Живое животное может решить остаться → честный BLOCKED и новый/другой допустимый site, НЕ удалять животное.
4. **Если NPC движется к препятствию**: уже реализованный measured BRAKE/ACTUAL_REST может применяться ТОЛЬКО если полная безопасная тормозная траектория вперёд реально проверена. Если safe corridor нет — STOP без нового акта, не делать фиктивную мгновенную остановку. Не менять `CLOCK_UNOBSERVED_ACTIVE_HOLD`, 4m/s²/MaxSpeed/1ms native velocity, all epochs/body/permission/water.
5. **Если contact случился после issue, в том числе unforeseen moving collider**: обязательно original `OBSERVED_UNSAFE/KINEMATIC_CLIP`, no accepted motion. Не «лечить» contact путем soft clear, перемещения другой сущности, телепортации, отключения коллизий/маски, попадания через Mesh или авто-despawn. Отдельные live случаи могут законно завершиться PARTIAL. Если нужен механизм выхода из реального взаимопроникновения — это **существенная новая физическая архитектура**, обсудить владельцу до изменений.
6. **Никаких автоматических атак Wolf2** в задаче021. Уклонение/ожидание — движение, боевое поведение «стрелять/убить/лутать хищника» имеет отдельное решение игрока. Выбор боя, агрессии и угроз будет обсуждаться; не выдавать NPC бесплатные патроны или убийства для clearing fixture.
7. **Защитные негативы**: static wall и closed Door всегда блокируют; native animal/foreign player/vehicle занимают коридор → BLOCKED/WAIT; неподвижный опасный overlap → STOP; animal moves into corridor between issue/witness → unsafe witness; объект ушёл → fresh safe body/route permits restart only from ACTUAL_SUPPORTED_REST; смена WorldKey, owner, position, collider instance, pending clock, duplicate receipt, stale nav poly, no supporting floor => STOP. Доказанное G4 не переписывать.

### Можно ли уменьшать вероятность случайного волка у дома?

Да, **динамический site selection** перед расходом материалов может измерять безопасный радиус, активные NPC и реальные пути до стройплощадки. Изменение выбора места без искусственного удаления волков допустимо. Но после оплаты нельзя переносить существующий дом/волка или создавать бесплатно второй набор. Если появляется угроза позже — безопасная остановка/отступление; данные partial-state остаются честными.
