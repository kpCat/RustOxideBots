# DECISION_GATE — когда обязательно согласование с владельцем

**Уже согласовано:** общий универсальный способ преодолевать препятствия и обходить их. Никакая дополнительная просьба «вам нужен универсальный механизм?» не нужна.

Codex **самостоятельно** решает: формат логов/типов C#, мелкие рефакторинги, компиляцию, исправления тестов/валидаторов, поиск API, подготовку безопасных E2E и cleanup.

**До архитектурно необратимых изменений** обязательно отправить владельцу короткую сравнительную записку и остановиться на согласование, если обнаружена развилка из следующих:

- оставить `RustNavMeshAgent` + native collision-aware mover, внедрить полноценный physics-aware controller, либо заменить фундаментальный способ физического перемещения;
- менять класс актора (`ScientistNPC : BasePlayer` на не-player entity), physics/collider настройки, решать коллизии путём изменения Rust world / server hooks;
- выбирать постоянную архитектуру взаимодействия с дверьми/склонами и дорогами, из-за которой существенно изменится поведение NPC, FPS или поддержка разных карт;
- вводить с существенными последствиями ограничение «боты не могут ходить по базам» либо специальную физическую имитацию вместо нативной механики.

Краткая форма обсуждения: `Вариант A / B / C → как работает → реалистичность → безопасность/баги → производительность (50–100 NPC) → поддержка Rust обновлений → стоимость реализации → моя рекомендация → что требует решения владельца`. Не просить разрешения на каждый тест и не менять план на бесконечные микроэтапы. При отсутствии ответа не выполняй опасную миграцию, продолжай только независимый безопасный анализ; честный итог.

Должен быть `docs/agent-tasks/RUST-BOTS-017-UNIVERSAL-OBSTACLE-TRAVERSAL/DECISION.md` при возникновении развилки и явно записанное согласованное решение пользователя в RESULT. Codex не должен объявлять собственную гипотезу уже согласованным выбором.
