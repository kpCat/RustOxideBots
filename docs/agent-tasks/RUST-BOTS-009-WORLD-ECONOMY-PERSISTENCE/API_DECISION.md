## Conservative identity strategy

Scope: two still-existing, partially harvested NATURAL nodes in the exact synthetic saved test world. World key includes installed compatibility fingerprint, input cache generation, exact input .sav and .map hashes. Completed JOURNEY proof additionally binds output generation/.sav, journal, economy state, actor state and inventory. RESTORE requires that exact completed save before launch.

For each source retain a journal incarnation UUID (a journal key, not engine identity), exact prefab/type, saved UID, position, quaternion rotation, scale, bounds, population name, item definition/startAmount, initial/current native pool/fraction and final health. Require one geometric candidate within 1 mm, matching geometry components within 0.001, and the same actual object observed in the native fromDisk hook with matching saved UID/prefab/health. The runtime object reference prevents transferring the witness to a later respawn. Validate all source plans before the first source mutation. Fresh/replaced/map-only/missing/ambiguous nodes refuse recovery; do not remove/create resources. This is deliberately narrower than universal persistent world identity.

If native pool equals expected depletion, NOOP. If exactly the recorded initial pool/fraction, subtract only the missing debit through DestroyFraction. Any other state, including lower or partially reset pool, refuses mutation. Repeat a fresh native-state evaluation; second pass must be NOOP. Synchronous neighbor pool/fraction snapshots must remain identical. Live identity/load-hook coverage is UNKNOWN until the independent second process.

## Durability and crash boundary

EconomyJournal schema 1 stores sequenced, SHA-256 chained, length-bounded binary bodies in newline-framed base64. Exclusive writer, UTF-8 validation, complete-tail check, durable FileStream.Flush(true) after each transition. Corruption, wrong binding and incomplete recovery fail closed. Existing zero-length files are corruption, not a new economy. Hashes detect accidents and proof mismatch, not a hostile administrator rewriting every artifact.

Gather: durable PREPARED with source/actor/tool/inventory before native hit; measured native conservation then APPLIED and COMMITTED. Craft: PREPARED -> DEBITTING -> DEBITED -> OUTPUT_CREATED -> COMMITTED, receipts include exact material/output UIDs. Restore opens only the bound existing journal before native inventory Load. Every recovered incomplete intent is IN_DOUBT and cannot advance/retry; committed intents cannot repeat either. No output is created from an intent on recovery.

Rust's source, inventory, plugin journal and native save are separate systems. Flush does not make them one transaction. Crash before/after hit, between ingredient debits, after output creation or before commit may lose state or leave uncertainty; recovery quarantines it and never compensates with a free item. Fault fixtures exercise the actual journal at five craft checkpoints; they are OFFLINE_ONLY, not a live killed-process experiment. Planned status ceiling: GREEN_WORLD_DEPLETION, CRASH_ATOMIC=NOT_PROVEN, CRASH_RECOVERY=OFFLINE_ONLY.

UNKNOWN / excluded: arbitrary map-only resource incarnations, legal respawn/wipe continuation, resource destruction/recreation, long-running multi-actor concurrency, native timed player craft queue, and production crash reconciliation. They are not inferred from a graceful restart.
