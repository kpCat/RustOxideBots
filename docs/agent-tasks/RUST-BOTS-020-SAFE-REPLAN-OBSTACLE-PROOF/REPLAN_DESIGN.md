# REPLAN DESIGN — переход к новому маршруту при ненулевой скорости

## Точная причина 019

В `ObstacleTraversal.TickCore` после принятой `MOTION_WITNESS` записывается `lastVelocity=velocity`; при `NO_BOUNDED_SUPPORTED_TRAJECTORY` вызывается `Obstacle(frame,"UNSUPPORTED_GAP",...)`. При доступной alternative native path `Obstacle` обновляет route/routeIndex, emits REPATH и **возвращает без actuation**. На следующем FixedUpdate `!pending && lastVelocity != 0` закономерно вызывает `CLOCK_UNOBSERVED_ACTIVE_HOLD`. Бюджет и фактическая скорость не подделаны; это согласованное fail-closed поведение по старому контракту, но recovery FSM неполон.

## Минимальное новое правило

`MOTION_WITNESSED_MOVING -> (1) DIRECT_SAFE_CONTINUATION | (2) BRAKE_TO_OBSERVED_REST -> REPLAN_COMMIT | (3) BLOCKED_WITH_REASON`, **не** `moving -> REPATH(no writer) -> active hold`.

- Если после witness есть безопасная локальная траектория, выдать следующую команду **в этом физическом callback** с полной fresh native route certificate/physical swept volume/support/permission/time/current body. Ограничить изменение направления/ускорения полным 3D вектором, без мгновенного разворота. Не повторять stale PATH старого nav epoch.
- Если безопасного нового вектора нет, но есть **реально свободный тормозной коридор** вдоль последней измеренной скорости, рассчитать ограниченное замедление физически допустимыми последовательными шагами. Каждый шаг — `MovePosition` только после полного precheck, затем independent actual motion witness на следующем FixedUpdate; максимальная скорость/ускорение/native velocity/clock as 018–019, нет fake zero. Не считать `Rigidbody` сам по себе решающим столкновение.
- `BRAKING` — самостоятельное состояние с bounded length/time/casts/attempts, без подмены `lastVelocity=0`, повторного расходования старых команд и скрытых мгновенных остановок. Строить временный коридор по фактическому физическому вектору, проверять преграды и `brakingDistance` (v²/2a + будущий dt + safety margin) **до выдачи**; если даже минимальная физически допустимая остановка не помещается в свободном пути/опоре — `BLOCKED / NO_SAFE_BRAKING_TRAJECTORY`, а не «пройти сквозь» или отпустить движение без witnesses.
- Только после одного или нескольких actual witnesses с финальным `observed/native velocity≈0`, поддержанной опорой, неизменной geometry/epoch/owner и без pending допускается **новый** `Plan` / commit replan. Если mid-brake меняются опоры/door/wipe/epochs/physics clock — STOP или осторожное safe replan только на действительно проверенной опоре; никакого сброса retry count по кругу.
- Explicit `HOLD` допускается только как команда на допустимую остановку после фактического торможения; нулевой `MovePosition` при движущемся `lastVelocity` за один шаг недопустим, если требует ускорения сверх4m/s².
- Сохранить старый `CLOCK_UNOBSERVED_ACTIVE_HOLD` негативным gate: nonzero velocity без pending/witness и без нового корректного режима recovery по-прежнему REJECTED. Нельзя просто удалить проверку, увеличить maxAcceleration/maxSpeed, reset clock/position, отключить real collider или объявить REPATH PASSED.
- Разделять `ROUTE_NO_SAFE_CANDIDATE`, `BRAKE_INSUFFICIENT_SPACE`, `BRAKE_SUPPORTED`, `REPATH_AFTER_REST`, `NATIVE_REPLAN_INVALID`, `REPLAN_BUDGET_EXHAUSTED`, `WITNESS_FAILED`. Актуальная native current-route policy NATIVE_CURRENT_ROUTE_V1 сохраняет глобальный PendingTiles telemetry; pending=true continuation остаётся недоказанной, не завышать scope.
- Позитивные offline tests: оставшаяся скорость с безопасным тормозным коридором, доказанная кинематика в пределах bound, остановка и повторный маршрут; негативные: стена за 1 см при v>0, чужой TC, дырка в полу, закрытая дверь, uphill step без cap, неподтверждённый шаг, wall gap, missed fixed tick, out-of-sequence, actual endpoint mismatch, fake rest, velocity zero reset, double replan, never-ending braking.

**Важно**: если выяснится, что при нынешнем `Rigidbody.MovePosition` нельзя физически выдержать такое торможение (или native Rigidbody останавливается иначе), отдельный measured engineering decision обязателен. Сохранять выбранную пользователем архитектуру C. Если нужно сменить actuator/controller principle — варианты владельцу с последствиями ДО внедрения.
